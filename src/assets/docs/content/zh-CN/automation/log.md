## 功能概述

**执行日志** 记录工作流节点的每一次执行尝试：节点运行、重试与错误摘要。它是排查运行失败的第一现场——按运行 ID 定位，查看每次尝试的状态、执行器与错误信息。

## 适用角色与前置条件

- **适用角色**：Agent 管理员（`automation:log:list` 权限）。
- **前置条件**：存在已执行的工作流运行。

## 进入路径

主菜单：**自动化中心 → 执行日志**。

## 操作步骤

### 1. 定位日志

- 按**运行 ID**（数字）精确检索；
- 或按**状态**筛选（运行中 / 成功 / 失败 / 等待重试）。

### 2. 分析尝试记录

列表按"尝试"维度展示：尝试 ID、运行 ID、节点运行 ID、尝试次数、状态、执行器、错误码与错误信息、起止时间。

> **提示** 一个节点失败后按策略重试，会产生多条尝试记录；`attemptNo` 标识第几次尝试。

### 3. 联动排查

- 从日志的 `runId` / `nodeRunId` 回到"运行实例"查看节点执行画布；
- 严重失败且无法恢复时，进入"失败任务"处理死信。

## 配置项说明

### 状态

| 状态 | 说明 |
|---|---|
| 运行中 | 尝试执行中 |
| 成功 | 尝试成功 |
| 失败 | 尝试失败（可能触发重试） |
| 等待重试 | 已安排重试，等待调度 |

### 关键字段

| 字段 | 说明 |
|---|---|
| 尝试 ID / 尝试次数 | 节点执行尝试的标识与序号 |
| 节点运行 ID | 关联的节点运行 |
| 执行器 | 执行该节点的 Worker |
| 错误码 / 错误信息 | 失败原因（供定位） |

## 常见问题

**为什么一个节点有多条日志？**
节点执行失败后按配置自动重试（如超时、临时故障），每次尝试各记录一行。

**日志保留多久？**
日志随运行数据保留，由平台运维策略决定；长期历史建议导出归档。

**错误信息不完整怎么办？**
结合"运行实例"的节点/时间线页签与"失败任务"的死信记录综合定位。

## 使用提示与边界

- 优先按运行 ID 过滤，避免海量日志干扰排查。
- 日志只读不可修改，用于审计与故障分析。
