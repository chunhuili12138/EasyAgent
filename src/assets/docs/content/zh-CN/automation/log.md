## 功能概述

**执行日志**按工作流节点的每一次执行尝试记录状态、执行线程、错误分类和起止时间。它适合回答以下问题：

- 本次工作流实际执行了哪些节点，每个节点调用了几次？
- 节点失败后是否进入自动重试，后续重试是否成功？
- 失败属于认证、限流、超时、业务校验还是其他类别？

执行日志不是通用应用日志，也不展示节点的原始输入、输出或完整异常堆栈。

## 适用角色与前置条件

- **适用角色**：租户的 Agent 管理员。
- **前置条件**：至少有一个工作流已经产生运行记录。

## 进入路径

主菜单：**自动化中心 → 执行日志**。

## 推荐排障流程

### 1. 从运行实例取得运行 ID

先在**运行实例**找到目标运行，复制其运行 ID。执行日志按尝试维度展示，先限定运行 ID 可以避免把不同运行的同名节点混在一起。

### 2. 筛选目标尝试

可组合使用以下条件：

| 条件 | 用途 |
|---|---|
| 运行 ID | 查看一次工作流运行的全部节点尝试 |
| 节点运行 ID | 只查看该次运行中的某个节点及其所有重试 |
| 状态 | 查看执行中、成功、最终失败或等待自动重试的尝试 |

输入条件后点击**搜索**。点击**重置**会清空条件并回到第一页。

### 3. 按尝试顺序定位原因

列表默认按开始时间从新到旧排列。同一个节点发生自动重试时：

- **节点运行 ID**相同；
- **尝试 ID**不同；
- **次数**从 1 开始递增。

建议先看状态和次数，再看错误分类、错误码、错误摘要，最后核对执行器与起止时间。

### 4. 联动处理

- 最后一条尝试为 **SUCCESS**：节点已经在后续重试中恢复。
- 最后一条尝试为 **RETRY_WAIT**：本次尝试失败，流程引擎正在按节点策略等待下一次自动重试。
- 最后一条尝试为 **FAILED**：自动重试已用尽或错误不可重试；到**失败任务**查看是否生成开放死信。
- 需要了解失败前后的节点关系：回到**运行实例**查看节点列表和时间线。

## 字段说明

| 字段 | 说明 |
|---|---|
| 尝试 | 单次节点调用记录的唯一 ID |
| 运行 ID | 所属工作流运行实例 |
| 节点运行 ID | 当前运行中某个节点的汇总记录；自动重试共用该 ID |
| 次数 | 当前节点第几次尝试，从 1 开始 |
| 状态 | 当前尝试的执行结果或重试等待状态 |
| 执行器 | 处理本次尝试的服务线程标识，主要供技术排障 |
| 错误分类 | 平台对失败原因的标准分类 |
| 错误码 | 更具体的机器可识别错误标识 |
| 错误摘要 | 面向排障的简要原因，不等同于完整异常堆栈 |
| 开始时间 / 完成时间 | 本次尝试的起止时间，不代表整个工作流的起止时间 |

### 尝试状态

| 状态 | 含义 | 下一步 |
|---|---|---|
| RUNNING | 本次尝试正在执行 | 稍后刷新；长时间不变化时结合服务状态排查 |
| SUCCESS | 本次尝试执行成功 | 无需处理 |
| RETRY_WAIT | 本次尝试失败且可重试，流程引擎等待下一次调度 | 刷新后检查是否出现更高次数的尝试 |
| FAILED | 本次尝试最终失败 | 查看错误分类，并到失败任务检查死信 |

### 错误分类

| 分类 | 常见含义 |
|---|---|
| VALIDATION | 输入、映射或输出不符合配置约束 |
| AUTH | 凭据无效、权限不足或认证失败 |
| RATE_LIMIT | 外部服务限流 |
| TIMEOUT | 节点或外部调用超时 |
| TRANSIENT | 临时网络或服务故障，通常可重试 |
| BUSINESS | 外部系统拒绝当前业务操作 |
| POLICY | 平台安全策略或执行策略拒绝 |
| CANCELLED | 操作已取消 |
| UNKNOWN | 暂未归入明确类别 |

## 完整示例

某 API 节点第一次调用超时，第二次调用成功：

| 次数 | 状态 | 错误分类 | 错误码 | 解释 |
|---|---|---|---|---|
| 1 | RETRY_WAIT | TIMEOUT | API_TIMEOUT | 首次调用结束并进入自动重试等待 |
| 2 | SUCCESS | - | - | 后续调用成功 |

两行应具有相同节点运行 ID、不同尝试 ID。若最后一行仍为 FAILED，再进入**失败任务**处理，不要把 RETRY_WAIT 误认为最终失败。

## 常见问题

### 为什么一个节点有多条记录？

节点按执行策略自动重试时，每一次实际调用都会生成独立尝试记录。这是正常的审计证据。

### 为什么 RETRY_WAIT 没有显示精确的下次重试时间？

当前页面记录本次尝试已经进入重试等待，但不展示 Flowable 作业的精确调度时间。重试间隔取自工作流节点的执行策略；通过刷新检查后续尝试是否产生。

### 为什么看不到请求参数和返回正文？

执行日志接口有意不返回节点原始输入和输出，避免密钥、个人信息或业务数据直接暴露在日志列表。请在授权范围内结合运行实例、外部业务系统审计记录和服务端日志核对。

### 可以导出日志吗？

当前页面只支持分页查询，不提供导出。不要把尚未提供的导出或长期归档能力作为操作步骤。

## 使用边界

- 日志只读且按当前租户隔离，不能在此修改或重新执行节点。
- **RETRY_WAIT** 是节点自动重试过程；**失败任务的安全重试**会创建新的工作流运行，两者不是同一操作。
- 页面展示错误摘要而非完整堆栈；代码异常仍需结合后端服务日志定位。
