## 功能概述

**触发器管理**为已发布工作流配置执行入口：Cron、Webhook、内部事件和审批回调。触发器可启用或停用，Webhook/审批回调通过签名密钥防止伪造请求。

## 适用角色与前置条件

- **适用角色**：拥有触发器查看/管理权限的 Agent 管理员。
- **前置条件**：至少存在一个工作流；启用触发器前必须先发布该工作流，自动化引擎也必须已启用。

## 进入路径

主菜单：**自动化中心 → 触发器管理**。

## 操作步骤

### 1. 新建触发器

1. 切换顶部类型：**Cron / Webhook / 内部事件 / 审批提供方**。
2. 点击**新建**，选择目标工作流并填写名称。
3. 按类型填写 Cron、Schema、事件类型或签名窗口，并按需要填写工作流输入和运行变量 JSON 对象。
4. 保存后启用触发器。Webhook/审批创建或轮换密钥后会显示一次密钥对话框，请立即复制保存。

### 2. 启用、停用和轮换

- 停用后不再创建新的运行实例，已有运行不受影响。
- Webhook/审批可点击**轮换密钥**。轮换后旧密钥立即失效，必须同步外部系统。

## 配置项说明

### 通用字段

| 字段 | 说明 |
|---|---|
| 工作流 | 目标工作流；启用时必须是已发布状态 |
| 名称 | 触发器名称，最长 100 个字符 |
| 工作流输入 | JSON 对象，作为工作流初始输入 |
| 运行变量 | JSON 对象，作为工作流运行变量 |

### Cron

| 字段 | 默认值/范围 | 说明 |
|---|---|---|
| Cron 表达式 | `0 0 * * * *` | Spring Cron 六段：秒、分、时、日、月、周 |
| 时区 | `Asia/Shanghai` | IANA 时区，调度器按该时区计算下一次执行时间 |
| 误触发窗口 | 300 秒，0–86400 | 服务暂时不可用时，允许错过的执行在窗口内补发 |
| 重叠策略 | `SKIP` | `SKIP`、`QUEUE`、`PARALLEL` 或 `REPLACE` |

Cron 直接创建运行实例，不写入事件记录。

### Webhook / 审批

| 字段 | 默认值/范围 | 说明 |
|---|---|---|
| 签名时间窗口 | 300 秒，30–3600 | 请求签名超过窗口会被拒绝 |
| Payload/回调 Schema | JSON Schema 对象 | 校验回调载荷；审批默认要求 `correlationKey` 和 `status` |

密钥只显示一次；丢失后请轮换，不要在普通配置或日志中保存明文密钥。

### 内部事件

| 字段 | 说明 |
|---|---|
| 事件类型 | 例如 `after_sales.acceptance`；保存和匹配时统一规范为小写 |
| Payload Schema | JSON Schema 对象，用于校验事件载荷 |

### 重叠策略

| 策略 | 行为 |
|---|---|
| `SKIP` | 存在活动实例时跳过本次触发 |
| `QUEUE` | 活动实例结束后补执行一次 |
| `PARALLEL` | 允许并行执行 |
| `REPLACE` | 终止活动实例并替换执行 |

## 常见问题

**为什么工作流下拉框里没有目标工作流？**
只有未归档工作流可编辑；启用触发器时，目标工作流必须已经发布。

**为什么事件类型写成大写仍然显示匹配？**
平台会将事件类型规范为小写。建议从配置、发布请求到外部系统统一使用小写，避免跨系统名称不一致。

**Webhook 密钥丢失怎么办？**
点击**轮换密钥**重新生成，并将新密钥、公开键和回调地址同步给外部系统。

**重新发布工作流后是否需要重建触发器？**
不需要。触发器使用工作流最新发布版本；重新发布后下一次触发会使用新版本。

## 使用边界

- Webhook 和审批回调地址、公开键和签名密钥属于敏感信息，只通过一次性对话框交付。
- Cron 使用配置的 IANA 时区计算时间；页面显示的下次执行时间可能与服务器本地时区不同。
- 事件触发器只匹配规范化后的小写事件类型，并按当前租户隔离。
