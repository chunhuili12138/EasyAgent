## 功能概述

**事件记录**是自动化事件链路的只读排查页面，分为两类记录：

- **发布记录（Outbox）**：只记录平台内部事件从业务事务进入待发布队列、再完成分发的过程。
- **接收记录（Inbox）**：记录内部事件、Webhook 和审批回调通过入口校验后的匹配、启动或恢复结果。

定时触发器不经过 Inbox/Outbox，而是由调度器直接创建运行。定时任务应到**运行实例**和**执行日志**查看。

## 适用角色与前置条件

- **适用角色**：拥有事件记录查看权限的 Agent 管理员。
- **前置条件**：已经发布内部事件，或已经创建并启用内部事件、Webhook、审批提供方。
- 本页面只读，不会重新发送事件、启动运行或修改触发器。

## 进入路径

主菜单：**自动化中心 → 事件记录**。

## 推荐排查顺序

### 1. 先选择记录方向

- 需要确认“内部事件是否已经发出”，选择**发布记录**。
- 需要确认“事件是否被接收、匹配、启动工作流或恢复审批等待”，选择**接收记录**。

切换方向时，页面会清空不兼容的状态和来源条件，避免使用 Inbox 状态筛选 Outbox，或反向误筛。

### 2. 使用对应筛选条件

两类记录都可以按**事件类型**和**状态**筛选。接收记录还可以按来源筛选：

| 来源 | 含义 |
|---|---|
| `INTERNAL` | 平台内部发布的事件 |
| `WEBHOOK` | 外部系统发送到 Webhook 触发器的请求 |
| `APPROVAL` | 外部审批提供方发送的审批回调 |

事件类型在保存与匹配时会规范为小写。建议统一使用小写字母、数字、点号、冒号、下划线或连字符，例如 `after_sales.acceptance`。

### 3. 先看状态，再用事件 ID 串联记录

#### 发布记录状态

| 状态 | 含义 | 下一步 |
|---|---|---|
| `PENDING` | 内部事件已写入 Outbox，等待后台分发 | 短暂等待并刷新；默认分发任务每 5 秒执行一次 |
| `PUBLISHED` | 分发事务已经完成 | 切到接收记录，使用事件类型和事件 ID 核对匹配结果 |

`PUBLISHED` **不代表存在匹配触发器，也不代表已经创建运行**。它只说明 Outbox 分发阶段完成。

#### 接收记录状态

| 状态 | 主要来源 | 含义 |
|---|---|---|
| `RECEIVED` | 内部事件 | 已写入 Inbox，正在匹配或处理 |
| `STARTED` | 内部事件、Webhook | 已匹配触发器并创建工作流运行 |
| `PROCESSED` | 审批回调 | 已处理回调，并关联原有的等待运行 |
| `UNMATCHED` | 内部事件 | 当时没有启用且事件类型一致的触发器 |
| `MATCHED` | 内部事件 | 原未匹配占位记录后来重新匹配成功 |
| `REJECTED` | 内部事件 | 已匹配某个触发器，但 Payload 不符合该触发器 Schema |

默认情况下，未匹配内部事件每 30 秒重新匹配一次。修正并启用触发器后无需重新发布原事件，等待后台重匹配并刷新即可。

同一个内部事件可能匹配多个触发器。此时会出现多条事件 ID 相同的接收记录，每个触发器分别对应自己的记录和运行；原 `UNMATCHED` 占位记录重新匹配后还会变为 `MATCHED`。

### 4. 继续查看运行结果

接收记录存在**运行 ID**时，转到**运行实例**查看固定工作流版本、节点轨迹和最终状态；需要定位节点重试或错误分类时，再到**执行日志**按运行 ID 查询。

审批回调不会创建新运行。`PROCESSED` 记录中的运行 ID 指向原先已进入审批等待的运行。

## 关键字段

| 字段 | 说明 |
|---|---|
| 事件 ID | 同一次请求或内部发布的幂等标识，可用于串联相关记录 |
| 事件类型 | 触发器匹配使用的业务事件名称 |
| 来源 | 仅接收记录可筛选；表示内部事件、Webhook 或审批回调 |
| 触发器 / 运行 | 仅接收记录有意义；分别指向命中的触发器和关联运行 |
| 载荷摘要 | Payload 的 SHA-256 摘要，不是原始正文 |
| 错误摘要 | 内部事件 Schema 拒绝或启动失败等可展示原因 |
| 发生时间 | 事件来源声明的发生时间 |
| 接收时间 | 接收记录写入 Inbox 的时间 |
| 处理时间 | Inbox 完成匹配、启动或回调处理的时间 |
| 发布时间 | Outbox 完成分发的时间 |

## 常见问题

### 发布记录已经是 PUBLISHED，为什么没有运行？

先切到接收记录，选择“内部事件”并按事件类型筛选。若记录为 `UNMATCHED`，检查触发器是否启用、事件类型是否一致、目标工作流是否已发布。若为 `REJECTED`，根据错误摘要修正触发器 Payload Schema。

### Webhook 或审批请求返回错误，但页面没有记录？

这是可能的正常结果。Webhook 和审批回调会在写入 Inbox 前校验公钥、时间戳、签名、JSON 正文和 Schema；任何一项失败通常都不会生成事件记录。请先查看调用方收到的 HTTP 响应，再核对触发器地址、密钥、签名原文、服务器时间和请求正文，必要时结合服务端日志排查。

### 为什么审批记录没有新运行？

审批提供方只恢复已有的审批等待节点，不负责启动新工作流。成功回调显示为 `PROCESSED`，运行 ID 指向原等待运行。

### 为什么定时任务没有事件记录？

Cron 由调度器直接创建运行，不使用事件收发链路。请到**运行实例**和**执行日志**查看。

## 使用边界

- 页面只展示载荷摘要，不展示完整敏感 Payload。
- Inbox/Outbox 按当前租户隔离。
- 事件记录用于诊断，不替代外部系统审计日志、调用方响应或服务端日志。
