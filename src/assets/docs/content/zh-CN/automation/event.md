## 功能概述

**事件记录**展示自动化事件的 Inbox/Outbox 生命周期，用于排查内部事件、Webhook 和审批回调是否已接收、匹配触发器并启动工作流。

Cron 触发器由调度器直接创建运行实例，不会生成事件记录；不要在事件记录中查找定时任务的每次执行。

## 适用角色与前置条件

- **适用角色**：拥有事件记录查看权限的 Agent 管理员。
- **前置条件**：已配置并启用事件、Webhook 或审批触发器，或平台已发布内部事件。

## 进入路径

主菜单：**自动化中心 → 事件记录**。

## 操作步骤

### 1. 切换 Inbox / Outbox

- **Inbox（接收记录）**：平台接收的内部事件、Webhook 或审批回调，以及匹配和启动结果。
- **Outbox（发布记录）**：平台发布的内部事件，等待调度器投递到匹配的事件触发器。

### 2. 检索与定位

按事件类型和状态筛选。列表提供事件 ID、事件类型、来源、状态、关联触发器/运行、载荷摘要、错误摘要和时间。

### 3. 排查未触发

- **UNMATCHED（未匹配）**：事件到达时没有启用的事件触发器匹配；修正触发器后，后台会周期性重新匹配。
- **REJECTED（已拒绝）**：载荷 Schema、签名或回调校验失败，按错误摘要修正来源系统或触发器配置。
- **RECEIVED（已接收）但没有运行 ID**：事件已入 Inbox，尚未成功启动工作流，继续查看错误摘要和后续状态。

## 来源与状态

### 来源类型

| 来源 | 说明 |
|---|---|
| `INTERNAL` | 平台内部发布并投递的事件；Outbox 记录在页面中也显示为内部来源 |
| `WEBHOOK` | 外部系统通过 Webhook 发送的回调 |
| `APPROVAL` | 外部审批提供方发送的审批回调 |

### 事件状态

| 状态 | 说明 |
|---|---|
| `PENDING` | Outbox 已创建，等待投递 |
| `PUBLISHED` | Outbox 已完成投递 |
| `RECEIVED` | Inbox 已接收，等待启动或处理 |
| `STARTED` | 已匹配触发器并创建工作流运行 |
| `PROCESSED` | 回调或事件处理完成 |
| `MATCHED` | 未匹配事件后来找到触发器并完成重新匹配 |
| `UNMATCHED` | 没有匹配的启用触发器，等待重新匹配 |
| `REJECTED` | 签名或 Payload Schema 等校验失败 |

### 事件类型大小写

事件类型会在保存和匹配时规范为小写。建议触发器和发布请求统一使用小写、数字、点号、冒号、下划线或连字符，例如 `after_sales.acceptance`；不要依赖大小写区分不同事件。

## 关键字段

| 字段 | 说明 |
|---|---|
| 载荷摘要 | 载荷的 SHA-256 摘要，不展示完整载荷 |
| 触发器 / 运行 | 匹配的触发器 ID 和工作流运行 ID |
| 错误摘要 | Schema、签名、重复事件或启动失败原因 |
| 发生/接收/处理时间 | 分别表示来源发生、平台接收和处理完成的时间 |

## 常见问题

**事件显示“未匹配”，但我刚创建了触发器？**
确认触发器已启用、事件类型拼写一致，并等待后台重新匹配；事件类型按小写规范化，不区分大小写。

**为什么 Cron 执行没有事件记录？**
Cron 是独立调度路径，直接创建运行实例；请到**运行实例**和**执行日志**查看。

**如何确认外部回调到达？**
切换到 Inbox，按 `WEBHOOK` 或 `APPROVAL` 的事件类型筛选；没有新记录通常表示请求未到达、签名校验未通过或触发器已停用。

## 使用边界

- 页面只展示载荷摘要和错误摘要，完整敏感载荷不会作为普通列表内容展示。
- Inbox/Outbox 数据按租户隔离；只能查看当前租户事件。
