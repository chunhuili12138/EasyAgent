## 功能概述

**运行统计**展示当前租户自动化运行的累计快照，包括运行状态、等待与排队、完成结果、节点重试、开放死信和执行耗时。它适合发现异常趋势并定位下一步排查入口，不是实时监控大屏，也不替代运行实例、执行日志和外部系统监控。

统计结果按租户缓存 **5 分钟**。页面上的刷新按钮会重新请求接口，但不会绕过尚未到期的缓存；请先查看“统计快照”时间，再判断新运行是否已计入。

## 适用角色与前置条件

- **适用角色**：Agent 管理员或系统管理员。
- **前置条件**：当前租户已产生自动化运行；执行核对修复时，自动化引擎及 Flowable 运行、历史和管理服务必须可用。
- 全部指标和核对范围均按当前租户隔离。

## 进入路径

主菜单：**自动化中心 → 运行统计**。

## 推荐查看顺序

### 1. 确认快照时间

先查看状态分布右上角的**统计快照**时间。新创建的运行、刚产生的节点重试或死信，最多可能要等当前 5 分钟缓存到期后才反映到指标中。

若只想查看最新业务运行，不要反复点击“核对并修复”；应到**运行实例**按时间和状态查询。

### 2. 判断规模与积压

| 指标 | 实际计算口径 | 排查方向 |
|---|---|---|
| 累计运行 | 当前租户保留的全部运行记录 | 用于理解总体规模，不代表某日吞吐 |
| 当前活跃 | 累计运行减去 `SUCCESS`、`PARTIAL_FAILURE`、`FAILED`、`CANCELLED` | 结合状态分布确认处于启动、运行还是等待 |
| 待启动与排队 | `CREATED` + `QUEUED` | 持续增加时检查引擎、并发、调度和依赖服务 |
| 当前等待 | `WAITING_EVENT` + `WAITING_TIMER` + `RETRY_WAIT` | 分别检查事件、定时等待和自动重试 |

`WAITING_EVENT` 既可能是普通事件等待，也可能是审批等待；结合运行详情时间线和**事件记录**判断正在等待什么。

### 3. 判断完成质量

| 指标 | 实际计算口径 |
|---|---|
| 完成运行成功率 | `SUCCESS ÷ (SUCCESS + PARTIAL_FAILURE + FAILED)` |
| 完成运行失败率 | `(PARTIAL_FAILURE + FAILED) ÷ (SUCCESS + PARTIAL_FAILURE + FAILED)` |
| 节点重试次数 | 节点尝试序号 `attemptNo > 1` 的记录数量 |
| 开放死信 | 状态为 `OPEN` 的失败任务数量 |

注意：

- `PARTIAL_FAILURE` 计入失败率。
- `CANCELLED` 不进入成功率或失败率分母。
- 存在完成运行时，成功率与失败率合计为 100%。
- 节点重试次数不是工作流级 `RETRY` 运行数量；它表示同一节点第 2 次及以后的执行尝试。
- 开放死信需要到**失败任务**逐条处理；对账不会替代安全重放或放弃死信。

### 4. 分析耗时

| 指标 | 实际计算口径 | 如何理解 |
|---|---|---|
| 实例平均耗时 | 同时有开始、完成时间的运行，从开始到完成的平均值 | 包含成功、失败、取消等已写入完成时间的运行 |
| 平均排队延迟 | 已开始运行从创建到开始的平均值 | 增大通常表示调度或执行容量不足 |
| 当前平均等待 | 当前处于三种等待状态的运行，从最近更新时间到现在的平均值 | 是当前等待年龄近似值，不是历史等待阶段平均值 |
| 节点平均耗时 | 已完成节点从开始到完成的平均值 | 增大时到执行日志和外部依赖定位慢节点 |

### 5. 使用状态分布定位明细

状态分布按当前租户全部运行分组，并以累计运行作为占比分母。确定异常状态后，到**运行实例**使用相同状态筛选，再查看具体运行的节点、尝试和时间线。

## 核对并修复

“核对并修复”不是普通刷新，而是会修改运行状态的运维操作。它最多扫描当前租户最近 **500 个带 Flowable 流程实例 ID 的运行**，逐个比较业务数据库、Flowable 活动实例、历史实例和引擎死信作业。

### 可以执行的修复

| 检测结果 | 修复行为 |
|---|---|
| 业务运行未终态，但 Flowable 存在死信作业 | 将业务运行标记为 `FAILED`，记录 `ENGINE_DEAD_LETTER`；不会自动重跑节点或清除外部副作用 |
| 业务运行已终态，但 Flowable 实例仍活跃 | 尝试终止残留引擎实例 |
| Flowable 活动实例不存在，历史实例已被删除 | 将业务运行标记为 `CANCELLED` |
| Flowable 活动实例不存在，历史实例正常结束 | 根据历史变量恢复为 `SUCCESS` 或 `PARTIAL_FAILURE`，并恢复可用输出 |

成功写入修复后会清除当前租户的统计缓存，页面随后重新加载新快照。

### 结果字段

| 字段 | 含义 |
|---|---|
| 扫描实例 | 本次实际检查的运行数，最大 500 |
| 已修复 | 成功更新业务运行或成功终止残留引擎实例的数量 |
| 业务已终态，但未能终止引擎实例 | 终止残留 Flowable 实例失败的运行 ID，需要结合服务端日志继续处理 |
| 引擎无活动实例，且历史终态无法确认 | 既无活动实例，又没有可确认完成时间的历史实例；系统不会猜测终态 |

自动化引擎启用时，后台默认每 5 分钟对所有存在运行数据的租户执行一次核对。手工核对用于处理明确的状态不一致，不应作为日常刷新操作。

## 常见问题

### 刚触发的运行为什么没有计入？

先查看统计快照时间。指标缓存 5 分钟，刷新按钮不会强制重新计算。需要实时查看时到**运行实例**查询；缓存到期后再刷新统计页。

### 当前等待很高，是否表示系统卡死？

不一定。审批等待、普通事件等待、定时器和自动重试都会计入。先按 `WAITING_EVENT`、`WAITING_TIMER`、`RETRY_WAIT` 分开查看，再结合事件记录和执行日志判断是否符合业务预期。

### 失败率为什么包含部分失败？

部分失败表示运行虽完成，但至少一部分业务项失败，因此平台将其纳入失败率。取消运行不代表执行失败，不参与成功/失败率。

### 核对并修复能重试失败任务吗？

不能。它只校正业务运行与 Flowable 引擎/历史状态，既不重跑节点，也不补偿或回滚外部 API。失败运行的恢复应在**运行实例**申请安全重试，开放死信应在**失败任务**处理。

## 使用边界

- 当前统计是累计快照，没有日期范围、工作流或触发器维度筛选。
- 指标用于发现异常，不单独证明某个外部业务操作成功或失败。
- 对账最多覆盖最近 500 个带引擎实例 ID 的运行，更早运行不在单次扫描范围内。
- 对账产生的状态修复会记录运行事件，但无法恢复已经缺失的外部业务证据。
