## 功能概述

**运行实例**保存工作流每次执行的历史轨迹，包括固定版本、触发方式、运行状态、节点执行、每次尝试、循环批次和事件时间线。本页用于回答三个问题：流程现在处于什么状态、在哪个节点发生了什么、是否可以安全取消或重试。

运行实例是执行证据，不是工作流配置页面。修改工作流草稿不会改变已经产生的运行。

## 适用角色与前置条件

- **适用角色**：拥有自动化运行查看权限的租户 Agent 管理员。
- **前置条件**：当前已切换到具体租户，并且工作流至少执行过一次。
- 运行数据按租户隔离；未选择租户时页面会提示先切换租户。

## 进入路径

主菜单：**自动化中心 -> 运行实例**。

## 查看运行列表

### 筛选

1. 在工作流下拉框按**名称或编码**搜索。下拉框同时包含当前工作流和已归档工作流，便于追溯历史运行。
2. 选择运行状态；留空表示全部状态。
3. 点击**查询**。点击**重置**清空条件并返回第一页。

### 列表字段

| 字段 | 说明 |
|---|---|
| 运行 ID | 本次执行的唯一编号，排查日志和事件时使用 |
| 工作流 | 工作流名称及稳定编码 |
| 版本 | 本次运行固定使用的发布版本，例如 `v2` |
| 触发方式 | 手动、定时、Webhook、内部事件、重试、子流程或 API |
| 状态 | 当前运行状态 |
| 耗时 | 从开始时间到完成时间；活跃实例按当前时间动态计算 |
| 错误码/错误摘要 | 运行级失败原因；节点级原因需要打开详情 |
| 开始时间 | 运行真正开始的时间，不是触发器计划时间 |

点击操作列的眼睛图标，或双击一行，打开运行详情。

## 运行状态

| 状态 | 含义 | 可执行操作 |
|---|---|---|
| `CREATED` | 运行记录已创建，尚未完成引擎启动 | 取消 |
| `QUEUED` | 已进入调度队列 | 取消 |
| `RUNNING` | 正在执行节点 | 取消 |
| `WAITING_EVENT` | 等待事件、审批回调或批量循环完成 | 取消 |
| `WAITING_TIMER` | 等待延迟定时器 | 取消 |
| `RETRY_WAIT` | 节点失败后等待下一次自动尝试 | 取消 |
| `SUCCESS` | 流程成功完成 | 查看 |
| `PARTIAL_FAILURE` | 失败被错误分支或继续策略处理，流程已结束 | 查看 |
| `FAILED` | 流程失败终止 | 查看、申请安全重试 |
| `CANCELLED` | 被用户或系统取消 | 查看 |

审批等待在运行层统一显示为 `WAITING_EVENT`，**不存在独立的“待审批”运行状态**。要确认等待的是审批还是普通事件，请查看执行画布、节点页和时间线。

## 查看运行详情

详情抽屉顶部显示状态、固定版本、触发方式、开始时间和耗时。重试运行还会显示源运行 ID 和第几次重试。

### 执行画布

执行画布使用本次运行的固定版本，不读取当前草稿。节点颜色表示状态：

| 颜色 | 状态 |
|---|---|
| 绿色 | 成功 |
| 红色 | 失败 |
| 橙色 | 运行中 |
| 蓝色 | 等待事件或定时器 |
| 灰色 | 尚未执行、跳过或其他状态 |

可使用画布右下角控件缩放、居中和查看缩略图。画布只用于查看，不能在这里修改节点或连线。

### 节点

节点页显示：

- 节点 ID 与节点类型；
- 当前状态和累计尝试次数；
- 错误码、错误摘要；
- 开始时间和完成时间。

本页不展示原始工作流输入、变量和节点输入输出正文，避免运行详情直接暴露业务载荷。需要定位数据映射时，应结合工作流只读 DSL、错误摘要和受权限控制的执行证据排查。

### 尝试

一个节点可能因为重试策略产生多条 Attempt。尝试页显示：

- Attempt 编号及所属节点运行 ID；
- 执行器标识；
- 状态、错误码和错误摘要；
- 开始时间、完成时间。

`RETRY_WAIT` 表示当前节点仍处于自动重试周期，不要同时对整个运行发起人工重试。当前页面不展示 Flowable 作业的精确调度时间；请按节点执行策略中的重试间隔判断，并刷新查看后续尝试。

### 循环批次

批量循环节点会生成批次和循环项。批次页显示：

| 字段 | 说明 |
|---|---|
| 批次 ID / 循环节点 | 定位本次批处理 |
| 状态 | 批次运行、待恢复或终态 |
| 已处理 | 已进入成功、失败或跳过终态的循环项数量 |
| 失败 | 已处理项中的失败子集，不应再次加到已处理数上 |
| 总计 | 批次快照中的循环项总数 |
| 并发 / 每秒限流 | 工作流发布时固定的批处理策略 |

点击列表图标可打开循环项抽屉，并按状态筛选。循环项包含标识、状态、尝试次数、错误摘要、下次重试时间和完成时间。

当前版本**不在运行实例页面提供终态循环失败项重试**。原因是原批次完成后已经恢复了工作流等待节点，终态后再次重放无法可靠恢复同一个流程位置。请保留失败证据，修正外部接口、数据或工作流配置后重新启动工作流。

### 时间线

时间线按创建时间展示关键执行事件，例如：

- 运行启动、完成、取消和重试；
- 节点开始、完成、失败和计划重试；
- 事件等待开始、外部事件接收和等待完成。

时间线显示事件类型、事件键和发生时间。Webhook、内部事件或审批回调的接收与匹配详情，应继续到**事件记录**核对。

## 取消运行

只有以下活跃状态显示取消按钮：`CREATED`、`QUEUED`、`RUNNING`、`WAITING_EVENT`、`WAITING_TIMER`、`RETRY_WAIT`。

1. 点击停止图标。
2. 核对运行 ID 后确认。
3. 平台终止仍存在的 Flowable 实例，并将运行及活动循环批次标记为取消。

取消不能恢复，也不会补偿或回滚已经完成的外部 API 调用。例如退款创建接口已经成功返回后再取消工作流，外部退款记录仍然存在。

如果流程在确认取消期间刚好完成，平台会保留实际终态并提示刷新，不会把已完成流程强行改成取消。

## 重试失败运行

只有 `FAILED` 状态显示重试按钮。点击后会先显示确认，再由后端执行安全检查。

重试不是从失败节点继续，而是：

1. 保留原失败运行不变；
2. 固定使用原运行的工作流版本和流程定义；
3. 读取原运行的输入、变量和触发载荷；
4. 创建一条触发方式为 `RETRY` 的新运行；
5. 在新运行上记录源运行 ID 和重试序号。

以下任一情况都会拒绝重试并返回冲突错误：

- 原运行不是 `FAILED`；
- 原版本或 Flowable 流程定义已不可重放；
- 原始未脱敏运行数据已经不可用；
- 工作流包含平台无法证明“无外部副作用”的节点。

API、Skill 等可能修改外部业务数据的节点通常不能自动证明安全，因此即使外部接口支持幂等，也可能被平台拒绝整条运行重放。此时应根据失败证据修正问题，再从工作流设计页面重新发起一次明确的新运行。

## 推荐排查顺序

### 运行失败

1. 先看列表的错误码和错误摘要。
2. 打开详情，在节点页找到第一个失败节点。
3. 在尝试页确认每次执行、重试等待状态和最终错误。
4. 到**执行日志**按运行 ID 查看完整 Attempt 记录。
5. 如果产生死信，到**失败任务**确认失败分类和处理状态。

### 长时间等待

1. 在画布确认等待节点是 `wait_event`、审批等待、批量循环还是延迟节点。
2. `WAITING_TIMER`：检查工作流配置的延迟时间。
3. `WAITING_EVENT`：到时间线确认等待事件键。
4. Webhook/内部事件/审批：到**事件记录**核对是否接收、匹配和处理。
5. 批量循环：查看批次及循环项是否仍在 `PENDING`、`RUNNING` 或 `RETRY_WAIT`。

### 部分失败

1. 确认错误是否被工作流失败出口或继续策略处理。
2. 检查外部业务结果是否符合“部分成功”的预期。
3. 不要把 `PARTIAL_FAILURE` 当作仍可继续的活跃状态；它已经是终态。

## 验收示例

以“自动生成退款申请”为例：

1. 工作流名称、固定版本和触发方式与本次操作一致。
2. 节点按 NL2SQL、LLM、Transform、API 的依赖顺序执行。
3. 每个节点 Attempt 数与配置的自动重试次数一致。
4. 循环批次已处理数不超过总数，失败数是已处理数的子集。
5. 时间线中的启动、失败/重试、等待和完成顺序与第三方业务记录一致。
6. 最终 `SUCCESS` 或 `PARTIAL_FAILURE` 有明确证据；`FAILED` 重试成功时会产生新的 `RETRY` 运行，原记录仍然保留。

## 常见问题

**为什么工作流筛选中还有已归档工作流？**

运行实例是历史证据。归档不会删除过去的运行，因此筛选列表保留已归档工作流。

**为什么运行一直显示等待事件？**

它可能在等待普通事件、审批回调或批量循环完成。打开详情查看等待节点，再结合时间线和事件记录判断外部信号是否到达。

**为什么审批通过后没有新运行？**

审批提供方不启动新运行。它恢复原来处于 `WAITING_EVENT` 的运行，所以应继续查看同一个运行 ID。

**为什么失败运行有重试按钮，点击后仍被拒绝？**

按钮表示该状态允许申请重试，不代表一定可重放。平台还会检查原版本、历史数据和节点副作用，任一项不安全都会拒绝。

**“部分失败”和“失败”有什么区别？**

`PARTIAL_FAILURE` 表示失败已走配置的错误出口或继续策略，流程已经结束；`FAILED` 表示流程失败终止，并且只有它可以申请整条运行安全重试。

**为什么看不到完整输入和节点输出？**

运行详情只展示诊断所需的状态、错误和时间信息，不直接渲染业务载荷。请通过受控的数据证据和工作流映射排查，不要把敏感正文复制到普通日志。

## 使用边界

- 运行固定使用创建时的发布版本，当前草稿或后续发布不会改变历史运行。
- 取消不会回滚已经成功执行的外部操作。
- 自动重试只允许平台能够证明安全的整条重放，不等同于“接口支持幂等就一定放行”。
- 终态循环失败项重试当前未形成可靠的流程恢复闭环，因此页面仅提供查看。
- 不要删除或掩盖失败、超时、取消和部分失败记录；它们是自动化验收、审计和问题复盘的重要证据。
