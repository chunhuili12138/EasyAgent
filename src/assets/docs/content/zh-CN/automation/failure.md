## 功能概述

**失败任务**保存工作流最终失败后产生的死信，用于确认失败是否仍需人工处理。它不是普通的自动重试队列，也不会自动修复原运行。

本页提供两种操作：

- **安全重试**：申请使用原固定版本和原运行数据创建一条新的 `RETRY` 运行；
- **放弃死信**：仅关闭待处理记录，表示不再从该死信申请重放。

处理前必须先核对失败节点、外部业务结果和副作用风险。

## 适用角色与前置条件

- **适用角色**：租户的 Agent 管理员。
- **前置条件**：工作流状态为 `FAILED`，并且最终失败节点已经产生死信。

## 进入路径

主菜单：**自动化中心 → 失败任务**。

## 推荐处理流程

### 1. 定位待处理死信

优先将状态筛选为**待处理（OPEN）**，也可填写运行 ID 精确查询。点击**重置**会清空条件并回到第一页。

列表中的失败类型只是标准分类。需要查看具体错误码和摘要时，使用运行 ID、节点运行 ID 到**执行日志**查询；需要确认已经执行过哪些节点时，到**运行实例**查看节点和时间线。

### 2. 核对外部业务状态

在采取任何恢复操作前，确认：

1. 自动节点重试已经结束；
2. 失败节点是否可能已经向外部系统提交请求；
3. 外部系统是否已经产生订单、退款、通知等业务结果；
4. 重复执行是否可能造成重复写入或重复通知。

页面不会自动完成外部系统对账。

### 3. 选择处理方式

#### 申请安全重试

仅 `OPEN` 死信显示安全重试按钮。确认后，平台调用与运行实例页相同的安全重放校验：

- 原运行必须仍为 `FAILED`；
- 原固定版本与 Flowable 流程定义仍可使用；
- 原始输入、变量和触发载荷仍存在且能够解密、校验；
- 工作流中的全部非控制节点都能被平台证明没有外部副作用。

校验通过后创建新的 `RETRY` 运行，并将死信标记为 `REPLAYED`。校验或创建失败时不会关闭死信，状态仍为 `OPEN`。

> `REPLAYED` 只表示新运行已经创建，不表示新运行执行成功。请到运行实例继续跟踪。

API、Skill 等可能调用外部业务系统的节点通常无法通过“无外部副作用”证明。即使外部接口支持幂等，平台也可能拒绝整条运行重放。

#### 放弃死信

在以下情况可以放弃：

- 业务已经人工处理；
- 该任务已过期或明确无需继续；
- 原运行不能安全重放，后续将通过修正配置后新建运行处理；
- 经核对，继续执行会造成重复业务操作。

放弃后状态变为 `DISCARDED`。当前页面不提供重新打开功能。

## 字段说明

| 字段 | 说明 |
|---|---|
| 死信 ID | 当前失败任务记录的唯一标识 |
| 运行 ID | 产生死信的原工作流运行 |
| 节点运行 ID | 最终失败节点的运行记录，用于关联执行日志 |
| 失败类型 | 最终失败的标准分类；悬停可查看原分类编码 |
| 状态 | `OPEN`、`REPLAYED` 或 `DISCARDED` |
| 处理人 | 执行安全重试或放弃操作的用户；无法解析名称时显示用户 ID |
| 创建时间 | 死信产生时间 |
| 处理时间 | 成功重放或放弃死信的时间 |

## 状态流转

| 状态 | 含义 | 可用操作 |
|---|---|---|
| OPEN | 死信仍待人工决策 | 申请安全重试、放弃 |
| REPLAYED | 已创建新的 `RETRY` 运行 | 只读；到运行实例跟踪新运行 |
| DISCARDED | 已确认关闭，不再从该死信重放 | 只读 |

`REPLAYED` 和 `DISCARDED` 都是死信处理终态，不会因为新运行后续成功或失败而改变。

## 失败类型与建议

| 类型 | 常见含义 | 处理建议 |
|---|---|---|
| VALIDATION | 输入、映射或输出不符合固定版本约束 | 原数据和版本不会随重放改变；修正输入或配置后发布新版本并新建运行 |
| AUTH | 凭据失效、权限不足或外部认证拒绝 | 修复凭据与权限，核对是否有副作用，再决定重放或新建运行 |
| RATE_LIMIT | 外部服务限流 | 等待限流窗口并核对外部结果；整条重放仍可能被安全检查拒绝 |
| TIMEOUT | 节点或外部调用超时 | 先确认外部操作是否实际完成，避免超时后重复提交 |
| TRANSIENT | 临时网络或服务故障 | 修复依赖后评估安全重放；不要仅凭分类直接点击重试 |
| BUSINESS | 外部系统拒绝业务操作 | 按业务原因修正数据或流程，通常应发起明确的新运行 |
| POLICY | 平台策略阻止执行 | 修正安全或执行策略，不应绕过策略重放 |
| CANCELLED | 操作被取消 | 确认取消来源与业务结果，再决定是否需要新运行 |
| UNKNOWN | 暂无更明确分类 | 结合执行日志和服务端日志定位后再处理 |

## 完整示例

某只读查询工作流因为数据库连接超时产生 `TIMEOUT` 死信：

1. 在执行日志确认节点自动重试已经用尽；
2. 确认流程只包含只读且可证明无副作用的节点；
3. 修复数据库连接后点击**安全重试**；
4. 平台创建新的 `RETRY` 运行，原死信变为 `REPLAYED`；
5. 到运行实例查看新运行是否成功。

如果同一流程包含创建退款的 API 节点，即使失败发生在查询节点，整条流程也可能因副作用无法证明而被拒绝重放。此时死信仍保持 `OPEN`，应核对业务结果、修正问题，再从工作流设计明确发起新运行。

## 常见问题

### 安全重试和运行实例的重试有什么区别？

两者使用同一套安全重放方法。失败任务操作成功后会额外把对应死信标记为 `REPLAYED`；运行实例重试不会处理死信。失败任务不是绕过重放限制的入口。

### 为什么有安全重试按钮，点击后仍被拒绝？

按钮只表示死信状态为 `OPEN`，允许提交申请。版本不可用、历史数据缺失、原运行不是 `FAILED`，或任一节点的外部副作用无法排除时，平台都会拒绝，死信仍保持 `OPEN`。

### 为什么列表没有具体错误信息？

死信只保存失败分类和关联 ID。请到执行日志查看错误码和摘要；完整技术异常需要结合服务端日志。

### 放弃死信会取消或回滚原运行吗？

不会。原运行已经失败终止，放弃只关闭死信，不会撤销已完成节点，也不会回滚或补偿外部 API 操作。

### 为什么处理人显示为用户 ID？

页面会优先解析当前租户中的有效用户名称。历史处理用户被停用或不再属于租户时，保留用户 ID 作为审计标识。

## 使用边界

- 所有查询和操作按当前租户隔离。
- 只有 `OPEN` 死信可操作；并发处理由后端锁与状态条件保护。
- 输入或工作流配置需要变化时，不能依赖安全重放，应发布新版本并新建运行。
- 放弃死信不会清理执行日志和运行证据。
