## 功能概述

**岗位管理** 按部门维护岗位体系：岗位编码与名称，用于用户归属与细粒度授权（文档密级"特定岗位"、Schema/工具授权范围等）。岗位必须挂靠在部门之下。

## 适用角色与前置条件

- **适用角色**：租户管理员（`system:post:list` 权限）。
- **前置条件**：已存在部门数据。

## 进入路径

主菜单：**系统管理 → 岗位管理**。

## 操作步骤

### 1. 新建岗位

1. 点击 **新建**，选择所属部门（必填）。
2. 填写岗位名称与编码（编码建议使用规范的英文/拼音标识，如 `sales_manager`）。
3. 设置排序与状态，保存。

### 2. 编辑岗位

可修改名称、所属部门、排序与状态；岗位被用户或 ACL 引用时建议先迁移引用再修改。

### 3. 删除岗位

点击 **删除** 移除岗位；已被用户或授权引用的岗位删除后相关授权将失效，请先调整。

## 配置项说明

| 字段 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| 所属部门 | 是 | - | 树形选择，岗位必须挂靠部门 |
| 岗位名称 | 是 | - | 展示名称 |
| 岗位编码 | 是 | - | 供系统引用；当前未强制校验唯一，建议在租户内保持稳定且不重复 |
| 排序 | 否 | 1 | 数字越大越靠后（min=1） |
| 状态 | 否 | 启用 | 启用 / 停用；停用岗位在用户分配下拉中不可选 |

## 常见问题

**为什么用户分配岗位时下拉为空？**
请确认目标部门下已创建**启用状态**的岗位；岗位分配下拉只显示所选部门下的启用岗位。

**岗位编码可以修改吗？**
可以编辑，但如已被 ACL 授权或系统引用，修改可能导致历史引用失效，建议保持稳定。

**岗位与角色有什么区别？**
岗位属于组织归属（决定数据范围与授权范围）；角色决定菜单与操作权限。两者配合使用。

## 使用提示与边界

- 岗位编码建议在租户内保持稳定、含义清晰且不重复，避免授权引用混淆；系统当前不强制校验编码唯一。
- 停用岗位会立即从用户分配与授权选择中消失，请评估影响后再操作。
