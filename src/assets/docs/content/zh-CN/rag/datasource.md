## 功能概述

**数据源管理** 用于维护租户业务数据库的**只读连接**，供 NL2SQL（自然语言转 SQL）受控查询使用。数据源只定义"如何连接"，数据可查的范围由其下的 **Schema 权限** 单独配置，实现按领域、按字段、按访问范围的精细化控制。

## 适用角色与前置条件

- **适用角色**：Agent 管理员（`rag:datasource:list` 权限）。
- **前置条件**：数据库已准备只读账号；目标表已创建为只读视图或脱敏视图（推荐）。

## 进入路径

主菜单：**Agent 管理 → 数据源管理**。

## 操作步骤

### 1. 新建数据源

1. 点击 **新建**，填写名称、编码、类型、JDBC URL、用户名与密码。
2. 设置最大连接数、查询超时和状态后点击 **保存**。新建时密码必填，已保存的密码不会回显。
3. 回到数据源列表，在该数据源的操作列点击 **测试连接**。连接失败时，根据提示编辑连接地址、账号或网络配置，保存后重新测试。

> **注意** 编码在保存后**不可修改**，请使用有意义的唯一编码（如 `sales_db`），供 Skill 与日志引用。

> **数据库驱动** 页面和后端会校验 MySQL、PostgreSQL、Oracle、SQL Server 四种 JDBC 地址格式，但当前标准发布包只内置 MySQL 驱动。使用其他数据库前，部署人员必须加入对应 JDBC 驱动并完成连接、方言和限行语法回归，否则“保存成功”不代表可以连接。

### 2. 配置 Schema 权限

1. 在数据源行点击 **Schema 权限**，进入该数据源下的 Schema 列表。
2. 点击 **新增 Schema**，填写领域编码、领域名称和视图名称。字段元数据和查询示例通过结构化表单维护，不需要手写 JSON。
   - **字段元数据**：每个允许查询的字段新增一行，填写字段名、数据类型和业务说明。数据类型支持筛选选择，也支持输入数据库特有类型。
   - **查询示例**：每个自然语言问题与已验证只读 SQL 新增一行。
   - **敏感字段**：从字段元数据下拉框中选择。字段改名后选择自动跟随，字段删除或清空后会自动移除。
3. 设置**访问范围**（公开/授权部门/授权岗位/授权用户）并选择授权对象。
4. 保存 Schema 后，在 Schema 列表操作列点击 **测试 Schema**。输入一个正常用户会提出的业务问题，系统会调用 LLM 生成 SQL，并以当前登录用户的 Schema 权限执行真实只读查询；页面最多预览 20 行。
5. 检查生成 SQL、返回行数和结果字段。至少覆盖正常查询、时间范围、枚举条件和聚合统计；若当前账号不在该 Schema 的授权范围内，测试会被拒绝。

### 3. 启用与维护

- **启用/停用**：停用后关联该数据源的 NL2SQL/Skill 步骤不可执行；
- **编辑**：密码留空表示不修改；
- **删除数据源**：若仍有**已启用**的 Skill 引用该数据源，系统会阻止删除；停用或调整这些 Skill 后，删除会同时移除其下全部 Schema 配置；
- **删除 Schema**：当前按单条 Schema 直接删除，不检查 Skill。删除或停用后，依赖该数据源的 NL2SQL 只能使用剩余可见 Schema；若没有可用 Schema，查询会被拦截。

## 配置项说明

### 数据源字段

| 字段 | 必填 | 默认值 | 说明 |
|---|---|---|---|
| 名称 | 是 | - | 展示用名称 |
| 编码 | 是 | - | 租户内唯一，保存后不可改 |
| 类型 | 是 | mysql | mysql / postgresql / oracle / sqlserver；标准发布包默认仅内置 MySQL 驱动 |
| JDBC URL | 是 | - | 含主机、端口、库名，建议带字符集/时区参数 |
| 用户名/密码 | 是 | - | 数据库只读账号 |
| 最大连接数 | 否 | 10 | 范围 1–100，建议 5–10 |
| 查询超时 | 否 | 30 | 范围 5–300 秒 |
| 状态 | 否 | 启用 | 停用后相关查询不可执行 |

### Schema 字段

| 字段 | 必填 | 说明 |
|---|---|---|
| 领域编码 / 名称 | 是 | 数据源内唯一；业务可读名称 |
| 视图名称 | 是 | 真实只读表或脱敏视图 |
| 字段元数据 | 强烈建议 | 通过表格逐行填写字段名、数据类型和业务说明，保存时自动序列化为 JSON 数组。非空时形成字段白名单并禁止 SELECT *。空列表不会限制可查询字段，生产配置不得留空 |
| 示例 | 否 | 通过表格逐行填写自然语言问题与已验证只读 SQL，保存时自动序列化为 `fewShotExamples` JSON 数组 |
| 允许函数 | 否 | `allowedFunctions` 数组。页面提供常用函数并允许自定义；非空时限制业务函数，系统内置的安全日期/空值函数仍可使用；空数组表示不额外限制函数 |
| 敏感字段 | 否 | 从字段元数据中选择物理字段名；元数据名称不存在时会自动移除，是字段白名单之外的额外防线 |
| 访问范围 | 是 | public / department / post / user（运行时按用户组织关系过滤） |
| 授权对象 | 按范围 | 部门/岗位/用户多选 |
| 状态 | 否 | 启用 / 停用 |

### Schema 复杂字段怎么填写

#### 字段元数据 `columnsMeta`

页面使用结构化表格维护字段，不再要求手写 JSON。每个允许查询的真实数据库列新增一行：

| 字段 | 是否必填 | 用途 |
|---|---|---|
| `name` | 是 | 真实列名，用于后端强制字段白名单；不能填中文展示名或 SQL 别名 |
| `type` | 是 | 真实数据库类型和精度，帮助模型正确比较、聚合和格式化；当前不用于 JDBC 类型校验 |
| `description` | 是 | 业务含义，写明单位、枚举值、时间语义、是否可聚合及关联关系 |

以下 JSON 仅用于说明保存后发送给后端的格式，页面中不需要手工填写：

```json
[
  {
    "name": "order_no",
    "type": "VARCHAR(32)",
    "description": "业务订单号，唯一标识一笔订单"
  },
  {
    "name": "status",
    "type": "VARCHAR(20)",
    "description": "订单状态：paid=已付款，shipped=已发货，completed=已完成"
  },
  {
    "name": "paid_amount",
    "type": "DECIMAL(12,2)",
    "description": "实付金额，单位元，可求和或取平均值"
  },
  {
    "name": "paid_at",
    "type": "DATETIME",
    "description": "付款时间，Asia/Shanghai 时区，用于按日或按月统计"
  },
  {
    "name": "customer_name_masked",
    "type": "VARCHAR(64)",
    "description": "脱敏后的顾客姓名，仅用于结果展示"
  }
]
```

非空数组会启用字段白名单并禁止 `SELECT *`；`name` 才决定允许查询的列，`type` 和 `description` 只帮助模型理解。空数组不会限制字段，生产配置不要留空。

#### 查询示例 `fewShotExamples`

页面使用查询示例表格维护，每行包含：

- `question`：业务用户真实会提出的自然语言问题；
- `sql`：已在目标数据库人工验证通过的单条只读 `SELECT`，只能使用本 Schema 的视图、字段和允许函数。

以下 JSON 仅用于说明保存后的后端格式，页面中不需要手工填写：

```json
[
  {
    "question": "查询已付款且实付金额大于 1000 元的订单",
    "sql": "SELECT order_no, paid_amount FROM v_after_sales_order WHERE status = 'paid' AND paid_amount > 1000 ORDER BY paid_amount DESC LIMIT 20"
  },
  {
    "question": "统计各订单状态的订单数",
    "sql": "SELECT status, COUNT(*) AS order_count FROM v_after_sales_order GROUP BY status ORDER BY order_count DESC"
  }
]
```

示例不能包含写操作、DDL、多条语句、命名参数、隐藏字段或其他表。不要固定某个用户、订单号或即将过期的绝对日期；少量示例用于解释最容易出错的枚举、时间和统计口径。

#### 允许函数 `allowedFunctions`

页面使用可创建的多选框，保存后对应函数名字符串数组，例如：

```json
["COUNT", "SUM", "AVG", "ROUND"]
```

应选择目标数据库实际支持的函数：MySQL 的 `DATE_FORMAT` 与 PostgreSQL 的 `DATE_TRUNC` 不能混用。空数组表示不启用额外函数白名单，并非禁止所有函数；严格环境只保留业务确实需要的函数。

#### 敏感字段 `sensitiveColumns`

从字段元数据下拉框中选择禁止 NL2SQL 引用的真实列名。可选项始终来自当前字段元数据；字段改名时选择跟随新名称，字段删除或清空时选择自动移除。

以下 JSON 仅用于说明保存后的后端格式，页面中不需要手工填写：

```json
["customer_phone", "id_card_number", "bank_card_no"]
```

这里填写物理列名，不是中文展示名、JSON 路径或脱敏别名。SQL 中出现这些标识符会被拦截，但此配置不能代替脱敏视图和数据库最小权限；最敏感字段应从视图中直接移除。

页面保存时会自动生成合法 JSON。字段元数据每行必须填写字段名、数据类型和业务说明，字段名不能重复；查询示例每行必须填写问题和 SQL，SQL 应是已验证的只读查询且只能使用当前 Schema 开放的范围。

## 配置示例

```json
{
  "domainCode": "sales",
  "domainName": "销售数据",
  "viewName": "v_sales_order",
  "columnsMeta": [
    { "name": "order_id", "type": "bigint", "description": "订单ID" },
    { "name": "region", "type": "varchar", "description": "销售区域" },
    { "name": "amount", "type": "decimal", "description": "订单金额" }
  ],
  "fewShotExamples": [
    { "question": "查询华东区本月订单总金额", "sql": "SELECT SUM(amount) FROM v_sales_order WHERE region='华东' AND order_date >= '2026-08-01'" }
  ],
  "allowedFunctions": ["COUNT", "SUM", "AVG", "ROUND"],
  "sensitiveColumns": ["customer_phone"],
  "visibility": "department",
  "allowedDepartmentIds": [1]
}
```

> **注意** NL2SQL 仅允许只读、单条查询，并受 Schema 范围、最大 1000 行与超时限制。进入 NL2SQL 执行器后的成功、拦截和失败尝试都会写入 SQL 审计，包括数据源不可用、无可见 Schema 和 SQL 生成失败；页面列表最多预览 Schema 测试结果的前 20 行。

> **测试说明** “测试 Schema”不是只生成 SQL 的预览操作，而是会对目标数据库执行真实 SELECT 查询并写入 SQL 审计。请使用只读账号和非敏感测试问题。

## 常见问题

**测试连接成功但测试 Schema 报错？**
请检查视图名称是否存在、只读账号是否具备查询权限，以及字段元数据中的字段名是否与视图一致。

**为什么 AI 生成的 SQL 总包含我没授权的字段？**
先确认字段元数据不是空数组。非空字段元数据才会启用字段白名单并阻止 SELECT *；同时将绝对禁止访问的列加入“敏感字段”，并优先从数据库视图中移除这些列。

**停用数据源后历史记录还在吗？**
在。停用只阻止新查询执行，历史 SQL 日志与审计记录保留。

**为什么 PostgreSQL、Oracle 或 SQL Server 能选择却连接失败？**
先确认部署包是否已加入对应 JDBC 驱动。类型选项同时用于地址校验与 SQL 方言，不能只修改类型或 URL；加入驱动后还要验证该数据库的账号权限、最大行数语法和常用函数。

## 使用提示与边界

- 建议数据库侧使用**只读视图/脱敏视图**承载查询，与应用层白名单形成双重防线。
- 访问范围过滤在运行时按用户组织关系生效，无需在 Schema 中配置行级 SQL 谓词。
- Schema 测试按当前登录用户的 ACL 执行；受限范围测试前，要把测试账号加入对应部门、岗位或用户授权。
- 删除数据源不可恢复；系统只阻止仍被**已启用 Skill**引用的数据源。停用 Skill 不会消除定义中的引用，后续重新启用前必须重新绑定有效数据源。
- 单独删除 Schema 没有引用保护且页面没有恢复功能，变更前应记录配置并先完成影响评估。
