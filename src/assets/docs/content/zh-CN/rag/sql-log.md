## 功能概述

**SQL 审计**记录 NL2SQL 执行器处理的自然语言查询及其结果，包括生成 SQL、实际受控 SQL、成功/拦截/失败状态、原因、耗时和结果行数。它用于检查 Schema 配置、安全策略和数据源运行质量，不是一个可直接执行或修改 SQL 的控制台。

数据源的 **测试连接**只检查 JDBC 连通性，不写 SQL 审计；Schema 的**测试 Schema**会真实调用 NL2SQL，因此会产生记录。

## 适用角色与前置条件

- **适用角色**：Agent 管理员（后端要求 `AGENT_ADMIN` 或 `SYS_ADMIN`）。
- **前置条件**：智能会话、Skill、自动化 NL2SQL 节点或 Schema 测试已调用 NL2SQL 执行器。

## 进入路径

主菜单：**Agent 管理 → SQL 审计**。

## 操作步骤

### 1. 查看统计与执行记录

- 顶部卡片显示当前租户的**总计 / 成功 / 拦截**数量，不随列表筛选变化。
- 后端也统计失败数量，但当前顶部没有失败卡片，可通过状态筛选查看。
- 列表显示自然语言查询、生成 SQL、状态、执行耗时、结果行数和创建时间。
- 生成 SQL 在列表中最多返回前 200 个字符；点击详情查看完整内容。
- 默认按创建时间倒序，支持 10 / 20 / 50 / 100 条分页。

### 2. 筛选记录

1. 关键字只匹配**自然语言查询**，不搜索 SQL 和原因。
2. 状态可选成功、拦截、失败。
3. 日期范围按记录创建日期筛选，包含所选结束日。
4. 点击**查询**应用条件；改变状态或日期也会立即查询。
5. 点击**重置**清空条件并返回第 1 页。

### 3. 查看与复制详情

点击**详情**查看：

- **自然语言查询**：交给 NL2SQL 的最终问题/提示文本；Skill 中可能来自 `query_hint`，不一定等于聊天原句。
- **生成 SQL**：LLM 返回并清理代码围栏、末尾分号后的 SQL。
- **最终执行 SQL**：系统补充最大行数限制后的 SQL；若尚未生成或在更早阶段失败，可能为空并回退显示生成 SQL。
- **状态**与**拦截/失败原因**。

生成 SQL 和最终 SQL 均可一键复制。复制只用于排查，不能在本页执行；如需数据库侧复现，请使用只读账号并确认 SQL 中不含敏感值。

### 4. 按状态排查

| 状态 | 优先检查 |
|---|---|
| 成功 `success` | 结果字段、行数和业务口径是否正确；成功不等于语义一定正确 |
| 拦截 `blocked` | 当前用户无可见 Schema、非 SELECT/危险语句、越权表/字段、通配符、未授权函数或敏感字段 |
| 失败 `failed` | 数据源不存在/停用、SQL 生成失败、缺少具体参数、SQL 语法、连接、账号权限、超时 |

处理建议：

1. 先读详情原因和最终 SQL。
2. 到**数据源管理 → Schema 权限**核对视图、字段元数据、函数、敏感字段、访问范围和状态。
3. 对连接/权限问题先执行**测试连接**，再用同一个可见用户执行**测试 Schema**。
4. 修改后用正常业务问题重新运行，并在 SQL 审计中确认出现新的成功记录；旧记录不会被覆盖。

## 记录产生阶段

进入 NL2SQL 执行器后，下列主要结果会写入审计：

| 阶段 | 典型状态 | SQL 字段 |
|---|---|---|
| 数据源不存在或停用 | failed | 生成/最终 SQL 为空 |
| 当前用户无可用 Schema | blocked | 生成/最终 SQL 为空 |
| LLM 无法生成 SQL | failed | 生成/最终 SQL 为空 |
| 生成了未绑定命名参数 | failed | 有生成 SQL，无最终 SQL |
| 安全或 Schema 范围校验拒绝 | blocked | 有生成 SQL 和加限行后的最终 SQL |
| 数据库执行异常 | failed | 有生成 SQL和最终 SQL |
| 数据库执行成功 | success | 有生成 SQL、最终 SQL、耗时和行数 |

平台会把无显式限行的查询限制为最多 1000 行，并同时调用 JDBC `setMaxRows(1000)`；页面只在 Schema 测试弹窗中预览前 20 行，SQL 审计本身不保存结果数据。

## 常见问题

**为什么自然语言查询看起来不像用户原话？**
Skill 或计划步骤可以把固定 `query_hint` 作为 NL2SQL 输入。审计记录的是实际交给执行器的文本，便于还原真实 SQL 生成条件。

**为什么成功记录的结果仍不符合业务口径？**
安全校验只证明 SQL 可安全执行，不证明模型理解正确。应完善领域描述、字段说明、枚举含义和 few-shot 示例，并用典型问题回归。

**为什么列表 SQL 不完整？**
列表为可读性只返回前 200 个字符；详情接口返回完整 SQL。

**可以删除或修改记录吗？**
当前页面没有删除、修改、重新执行或导出操作，记录用于租户内追溯。

## 使用提示与边界

- SQL 审计与操作审计不同：前者记录 NL2SQL 处理结果，后者记录 HITL 决策。
- 页面按租户隔离，但 SQL 可能包含业务条件或字面值，仍需限制 Agent 管理权限。
- 结果行内容不写入 SQL 审计；需要核对数据时，应在受控的 Schema 测试或实际业务问答中复现。
- 审计写入异常会记录服务器警告但不会反向改变查询结果，因此合规场景还应监控 SQL 审计写入失败日志与指标。
