## 功能概述

**SQL 审计** 记录所有 NL2SQL 查询的生成与执行情况：用户提问、生成 SQL、最终执行 SQL、执行状态与耗时。被安全策略拦截的查询也会记录拦截原因，便于排查与审计。

## 适用角色与前置条件

- **适用角色**：Agent 管理员（`rag:sql-log:list` 权限）。
- **前置条件**：已配置数据源与 Schema，且会话中产生过 SQL 查询。

## 进入路径

主菜单：**Agent 管理 → SQL 审计**。

## 操作步骤

### 1. 查看执行记录

- 顶部统计卡展示**总计 / 成功 / 拦截**数量；
- 列表展示自然语言查询、生成 SQL、状态、耗时与结果行数。

### 2. 查看 SQL 详情

点击 **详情** 查看：

- **生成 SQL**：模型生成的原始 SQL（可复制）；
- **最终执行 SQL**：实际执行的 SQL（可复制，无则回退显示生成 SQL）；
- **拦截原因**：被安全策略拦截时的具体原因（红色标识）。

### 3. 排查问题

- **拦截**：根据拦截原因调整提问方式或修正 Schema 配置；
- **失败**：结合错误信息检查数据源连通性、视图权限等。

## 配置项说明

### 状态

| 状态 | 说明 |
|---|---|
| 成功 | SQL 执行成功并返回结果 |
| 拦截 | 被安全策略拦截（只读校验、Schema 范围、函数白名单、敏感字段等） |
| 失败 | 执行异常（连接失败、语法错误、超时等） |

### 列表字段

| 字段 | 说明 |
|---|---|
| 自然语言查询 | 用户的原始提问 |
| 生成 SQL | 模型生成的 SQL（等宽字体展示） |
| 耗时 | 执行耗时（毫秒） |
| 结果行数 | 返回的数据行数 |

## 常见问题

**为什么查询被拦截？**
NL2SQL 执行只读、单条、Schema 允许范围等安全策略；例如查询了未授权字段、使用了非白名单函数或试图写入数据时会被拦截。

**生成 SQL 与最终执行 SQL 有什么区别？**
最终执行 SQL 是经过安全检查与改写后实际执行的语句；两者不一致时以最终执行 SQL 为准。

**如何减少 SQL 失败率？**
确保 Schema 字段元数据与视图一致、few-shot 示例贴近实际提问，并保证数据源账号可用。

## 使用提示与边界

- 所有 SQL 均记录日志，用于安全审计与质量分析，不可删除。
- 发现频繁拦截时，优先检查 Schema 配置（字段白名单、允许函数）是否合理。
