## 功能概述

**Bad Case 分析**集中管理用户在智能会话中提交的负面反馈。管理员可查看原问题、模型回答、反馈原因和检索结果，填写正确回答，供质量分析和后续数据导出使用。

## 适用角色与前置条件

- **适用角色**：拥有 Bad Case 查看/标注权限的 Agent 管理员。
- **前置条件**：用户在智能会话中对回答提交反馈。

## 进入路径

主菜单：**Agent 管理 → Bad Case 分析**。

## 操作步骤

### 1. 筛选与查看

- 使用关键词、状态和日期范围筛选；当前页面提供**待标注**和**已标注**筛选。
- 列表显示用户问题、反馈类型、补充说明、状态和创建时间。
- 点击**详情**查看会话 ID、消息 ID、完整问题、AI 回答、检索结果和已有正确回答。

### 2. 标注

1. 对 `pending`（待标注）记录点击**标注**。
2. 核对原问题、AI 回答、反馈类型、补充说明和检索结果。
3. 填写必填的**正确回答**并保存，状态变为 `labeled`（已标注）。

正确回答用于质量治理和后续导出，不会自动替换线上模型回答，也不会自动写入知识库。

## 反馈类型

| 类型 | 含义 |
|---|---|
| 事实不符 | 回答与事实或知识库内容不一致 |
| 未遵循指令 | 未按要求的形式或范围回答 |
| 格式问题 | 输出格式不符合预期 |
| 内容错误 | 回答存在错误内容 |
| 回答不完整 | 遗漏关键事实或步骤 |
| 回答不相关 | 答非所问 |
| 其他 | 其他问题 |

## 状态

| 存储状态 | 页面含义 | 说明 |
|---|---|---|
| `pending` | 待标注 | 等待管理员填写正确回答 |
| `labeled` | 已标注 | 已填写正确回答，等待质量治理或导出 |
| `exported` | 已导出 | 供后续数据导出流程使用；当前页面没有手动推进到该状态的操作 |

当前版本没有“已处理”状态，也不会在标注后自动把记录推进为 `exported`。

## 常见问题

**为什么没有数据？**
Bad Case 由聊天反馈自动创建；请确认用户对不满意回答点击了反馈，并且当前租户和筛选条件正确。

**标注后会立即修正回答吗？**
不会。标注结果只进入质量分析和后续导出流程；要修正线上回答，需要调整知识库、检索配置、Skill 或模型提示词。

**详情里的检索结果有什么用？**
用来判断根因：知识缺失、检索未命中、权限过滤，还是模型理解/生成错误。

**可以删除 Bad Case 吗？**
当前页面没有删除操作；请保留记录以便审计和质量追踪。

## 使用边界

- 记录按租户隔离，详情中的问题、回答和检索内容可能包含敏感业务信息，应按最小权限分配标注权限。
- 批量出现同类反馈时，应优先分析共同的知识、权限或提示词问题，而不是只修改单条正确回答。
